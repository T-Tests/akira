# Operations

## Rollout

These are migrations for the existing Supabase database, not a move to another provider. No migrations or Edge Functions are automatically deployed by this repository. An automatically deployed frontend will not work correctly with the old database; coordinate the rollout and expect downtime until all steps are complete.

1. Back up the database and test the complete rollout on a disposable Supabase project first. Pause scheduled workflows, wait for in-flight runs to finish, and prevent on-demand lookup requests during the upgrade. The new GitHub workflows skip jobs until the repository Actions variable `AKIRA_COMMUNITY_READY` is set to `true`; this does not stop older runs already in progress.
2. Check which migrations have actually been applied. For a database through `0006`, apply `supabase/migrations/0007_human_review.sql` first. If it is already applied, do not apply it again. Then run `0008_community_reviews.sql` and `0009_global_discovery.sql`, in that order. In the Supabase Dashboard SQL Editor, paste the **contents** of each file, not its path, and run each inside its own `begin;` / `commit;` transaction. Stop and investigate any error; do not continue with a partially applied migration. Fresh projects need `0001` through `0009` in order.
3. Migration `0008` disables the old anonymous one-click review RPC, which otherwise bypasses Kids votes. Previously unpublished `llm_tagged` films remain unpublished and are not automatically moved into the new queue; handle that backlog deliberately with trusted review tools. Previously published Kids films remain visible as `legacy`.
4. Configure Supabase Auth as below, deploy the updated `lookup` Edge Function and frontend, and verify Kids discovery, Adults discovery, search, sign-in, voting and global offers before resuming requests. Older clients and functions do not enforce the new Kids rules; coordinate them with the migration.
5. In GitHub **Settings → Secrets and variables → Actions → Variables**, set the repository variable `AKIRA_COMMUNITY_READY` to `true` only after the database and function are ready. Verify the next scheduled run. The same gate applies to the manual global-ingest workflow. To pause new runs, remove the variable or set it to `false` and separately cancel any already-running jobs.

Enable email confirmation in Supabase Auth and configure its site URL and redirect allowlist for the deployed and local origins. Configure production email delivery and rate limits. Browsing remains anonymous; voting requires an email-confirmed account. Email verification and one vote per account do not prevent multiple accounts or guarantee accurate reviews. Monitor reports and act on unsafe entries.

Previously published Kids-eligible movies retain their visibility as `legacy`. Previously unpublished movies, including manually withdrawn ones, are not automatically republished. Newly tagged films appear in Adults after one AI pass; Kids-eligible films enter community review. At least five approvals and an approval majority are required for Kids; a rejection majority moves the film to the rejected review tab. Votes and status can change. Change the single `kids_review_settings.approval_threshold` row using a trusted database session; community statuses are recalculated.

To withdraw an unsafe movie from both audiences, run `npm run review -- --unpublish <tmdb_id>` or `--reject <tmdb_id>`. `--approve <tmdb_id>` is a trusted override that bypasses community voting for Kids-eligible films. Keep the service-role key and database credentials off the client. If a rollback is needed, pause jobs, restore a tested database backup and deploy the matching previous frontend and Edge Function together; old versions cannot safely interpret the new per-audience states.

Streaming offers are global but labeled by country. The weekly regional discovery jobs still discover in six regions; `npm run ingest:global -- --refresh-oldest 15000` refreshes all TMDB regions for the oldest published films. Repeat to backfill existing titles and monitor database size and workflow runtime. Newly discovered films can initially have only their discovery-region data until refreshed. Missing TMDB coverage is not evidence that a film is unavailable everywhere.

Run `tests/community.sql` only against a disposable migrated Supabase database as a privileged database user. The transaction rolls its fixtures back. Check authentication redirects, actual email delivery, concurrency, Edge Function permissions, global backfill, and end-to-end flows in a staging project as well.

## Provider feasibility

- **Gemini:** [Live API](https://aistudio.google.com/docs/live-api) is for real-time audio/vision over WebSockets, not batch JSON tagging. A normal [Gemini Flash text model](https://aistudio.google.com/docs/openai) is a better candidate and has an OpenAI-compatible endpoint. For recent films, compare permitted source material and optionally [Google Search grounding](https://aistudio.google.com/docs/google-search); a newer model alone cannot guarantee accuracy. Evaluate schema compliance, factual accuracy, latency, quotas, privacy and [pricing](https://aistudio.google.com/docs/pricing) on representative films before switching. No live model comparison has been performed.
- **Zoho Catalyst:** the app's `out/` is static, making Webclient Hosting a plausible frontend-only migration while retaining Supabase and GitHub Actions. [Catalyst's free tier](https://catalyst.zoho.com/free-tier/) advertises renewable monthly usage, with charges after limits; confirm hosting quotas, custom domains, redirects, TLS, deployment, actual costs and rollback in an account before committing. Zoho says no card is required for the free tier, but a card is required for optional trial credits. [Cloudflare supports changing the account `workers.dev` subdomain](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/) or using a custom domain; changing it may affect other Workers and existing links. No hosting migration or account change has been performed.
